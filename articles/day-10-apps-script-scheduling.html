讓重大訊息瞭望台每天自動啟航

Apps Script 排程解說篇：從「會跑的程式」跨到「會自己工作的流程」。

Arthur Agent 編輯室2026 年 7 月 5 日約 10 分鐘閱讀
實際案例船長每天早上 7 點起床按「執行」，這不叫自動化——這叫有鬧鐘的手動化。

Day 09 的瞭望台已經會讀取公開資料、去重並寄信；今天替它裝上真正的出航時刻表。

先確認船能航行，再設定它自動出港。排程不會修好錯誤，只會讓錯誤準時發生。

Apps Script 的碼頭在哪裡？

前往 script.google.com，登入 Google 帳號即可建立專案。一般 Gmail 與 Google Workspace 帳號皆可使用，但公司或學校管理員可能限制外部連線、授權或寄信功能。

Apps Script 主要使用 JavaScript，適合串接 Gmail、Sheets、Drive 與外部 API。第一次執行 Day 09 程式時，Google 會要求外部連線與寄信權限；它不需要把 Gmail 密碼寫進程式，但你仍應閱讀授權範圍，而不是像喝醉的水手一樣對所有按鈕都喊「同意」。

Apps Script 和 Colab，該搭哪一艘船？

比較Apps ScriptGoogle Colab
主要語言JavaScriptPython
強項Google 服務與輕量自動化資料分析、模型與互動實驗

部分付費或企業環境可能提供額外排程能力，因此不是「Colab 永遠不能排程」；但對這個初學者每日寄信案例，Apps Script 的權限與觸發器路徑更直接。

設定前的三項檢查

  1. 主程式手動成功：Day 09 的函式名稱是 monitorTsmcMajorMessages，先確認它能取得資料且在有新公告時寄信。
  2. 授權已完成：時間觸發器以建立者帳號執行；未授權的服務不會因為設了鬧鐘就突然變聽話。
  3. 專案時區正確：在專案設定確認時區為 Asia/Taipei，否則「早上 7 點」可能在另一片海域出現。

方法一：在畫面上建立每日觸發器

  1. 開啟 Day 09 的 Apps Script 專案。
  2. 左側點選鬧鐘圖示「觸發條件／Triggers」。
  3. 點選「新增觸發條件／Add Trigger」。
  4. 執行函式選 monitorTsmcMajorMessages。
  5. 事件來源選「時間驅動／Time-driven」。
  6. 類型選「日期計時器／Day timer」。
  7. 時段選「上午 7 點到 8 點」。
  8. 儲存並確認觸發器出現在清單中。

Apps Script 會在所選小時內挑選一個時間執行，不保證精準在 07:00:00。這是巡邏船，不是火箭發射。

方法二：用程式建立，而且避免重複鬧鐘

Day 09 已提供 createDailyTrigger。以下版本會先刪除同一函式的舊觸發器，再建立新的每日 7 點觸發器，避免你按三次就收到三隊瞭望兵同時大喊。

TRIGGER SETUP
function createDailyTrigger() {
  ScriptApp.getProjectTriggers()
    .filter(function (trigger) {
      return trigger.getHandlerFunction() === "monitorTsmcMajorMessages";
    })
    .forEach(function (trigger) {
      ScriptApp.deleteTrigger(trigger);
    });

  ScriptApp.newTrigger("monitorTsmcMajorMessages")
    .timeBased()
    .everyDays(1)
    .atHour(7)
    .create();
}

只需手動執行 createDailyTrigger 一次。若日後改時間，再執行一次即可替換舊觸發器。

自動執行後，去哪裡看它有沒有撞礁？

左側「執行項目／Executions」會列出每次執行的時間、函式、狀態與錯誤。可安裝觸發器失敗時，Google 通常也會寄送失敗摘要。你應至少確認：

  • 最近一次排程是否成功；
  • 是否因 API 格式、網路或授權變更而失敗；
  • 是否因 Day 09 的去重機制而合理地沒有寄信；
  • 剩餘寄信配額是否足夠，可用 MailApp.getRemainingDailyQuota() 查看；
  • 不再使用時是否已刪除觸發器與撤銷不需要的權限。

常見的三艘幽靈船

一、選錯函式

若選了 createDailyTrigger 當每日任務，它每天只會重建鬧鐘。真正要排程的是 monitorTsmcMajorMessages。

二、沒有信就以為沒執行

Day 09 設計成「沒有新公告就不寄信」。請看 Executions 與日誌，不要用收件匣沉默直接判定失敗。

三、建立多個相同觸發器

多個觸發器會重複執行。雖然去重能降低重複寄信，仍會浪費配額並增加混亂；定期檢查觸發器清單。

解決案例

船長睡過頭，瞭望台仍準時巡航

使用者先手動測試、完成授權並確認 Asia/Taipei 時區，再建立每天 7–8 點的觸發器。隔日 Apps Script 在時段內自動執行，沒有新公告便只留下成功紀錄；第三日出現新公告，系統寄出一次通知。船長晚了半小時起床，世界沒有因此停止運轉——這才叫自動化。

結語：設定時刻表，不等於放棄掌舵

自動化的價值，是把固定動作交給系統，把人的時間還給判斷。你負責方向、規則與覆核；AI 協助畫圖；Apps Script 每天出航。只是別忘了偶爾看看航海日誌——沉默有時代表風平浪靜，有時代表船早就不見了。
